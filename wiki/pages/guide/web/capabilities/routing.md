# Routing

The routing capability provides a framework view of the routes generated by OdbVue's file-based routing. It adapts Vue Router route records into pages with a predictable title, route metadata, and navigation metadata.

Use it when an application shell, navigation component, breadcrumb trail, or page-aware component needs to understand the current route or all available pages. It does not create routes or enforce authorization. Routes continue to be generated from files in `src/pages`, and application code remains responsible for route guards and access enforcement.

## How it works

`useRouting()` reads the active Vue Router instance and returns computed values:

| Value           | Description                                                     |
| --------------- | --------------------------------------------------------------- |
| `pages`         | Navigable, ordered root-level pages.                            |
| `allPages`      | Every registered route, adapted to an OdbVue page.              |
| `currentPage`   | The deepest route record matched by the current URL.            |
| `currentModule` | The module declared by the current page metadata.               |
| `breadcrumbs`   | Visible pages along the current URL hierarchy.                  |
| `title`         | A function that resolves a registered page title by path.       |
| `params`        | Normalized path and query parameters for the current route.     |
| `navigate`      | Vue Router's programmatic navigation function.                  |

Each page exposes its route path, the original normalized Vue Router record, `meta`, a derived `title`, and `navigation` metadata. A title comes from `meta.title` when present; otherwise it is derived from the final path segment, so `/customer-orders` becomes `Customer Orders`.

```ts
import { useRouting } from '@odbvue/web'

const { allPages, breadcrumbs, currentModule, currentPage, navigate, pages, params, title } = useRouting()
```

The returned values are Vue computed refs. Read their values in script with `.value`; Vue automatically unwraps them in templates.

## Page metadata

Declare metadata with `definePage()` in a page component. The routing capability reads this metadata from Vue Router and makes it consistent for framework UI.

```vue
<script setup lang="ts">
definePage({
  meta: {
    title: 'Customers',
    description: 'Search and maintain customers.',
    icon: '$mdiAccountGroup',
    order: 20,
    layout: 'default',
    visibility: 'with-role',
    access: 'with-role',
    roles: ['sales'],
  },
})
</script>
```

`visibility`, `access`, `roles`, and `permissions` describe the page for application UI and guards. They are not authorization by themselves: use a route guard or other application policy to make the access decision.

## Practical examples

### Build a navigation list

`routing.pages` is already filtered and ordered for application navigation. A page's `navigation` metadata is `false` when it sets `navigation: false`, `hidden: true`, or `visibility: 'never'`. Otherwise it contains the explicit navigation settings or inherits the page icon and order.

```vue
<script setup lang="ts">
import { useRouting } from '@odbvue/web'

const { pages } = useRouting()
</script>

<template>
  <v-list nav>
    <v-list-item
      v-for="page in pages.value"
      :key="page.path"
      :to="page.path"
      :prepend-icon="page.meta.icon || '$mdiMinus'"
      :title="page.navigation === false ? page.title : page.navigation.label || page.title"
    />
  </v-list>
</template>
```

To customize a label without changing the page title, use nested navigation metadata:

```ts
definePage({
  meta: {
    title: 'Customer administration',
    navigation: { label: 'Customers', icon: '$mdiAccountGroup', order: 20 },
  },
})
```

### Render breadcrumbs

Breadcrumbs are built from each URL prefix that has a registered, visible page. For `/customers/42`, create pages for `/`, `/customers`, and `/customers/:id` to render a complete trail.

```vue
<script setup lang="ts">
import { useRouting } from '@odbvue/web'

const { breadcrumbs } = useRouting()
</script>

<template>
  <v-breadcrumbs :items="breadcrumbs" />
</template>
```

### Adapt the current page

Use `usePageMeta()` when a component only needs metadata from the current page. This is useful for page headers and layout-level UI.

```vue
<script setup lang="ts">
import { usePageMeta } from '@odbvue/web'

const pageMeta = usePageMeta()
</script>

<template>
  <v-toolbar-title>{{ pageMeta.title || 'OdbVue' }}</v-toolbar-title>
</template>
```

### Detect the active module

`currentModule` is declared in page metadata and is `undefined` when the current page has no `module`. A layout can use it to select module-specific UI without parsing paths.

```ts
import { computed } from 'vue'
import { useRouting } from '@odbvue/web'

const { currentModule } = useRouting()
const isCustomersModule = computed(() => currentModule.value === 'customers')
```
